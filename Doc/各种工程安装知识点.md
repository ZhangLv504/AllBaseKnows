# 1.1 VSCode + Python 虚拟环境配置与依赖管理完整指南

本教程适用于在 **Windows** 或 **Linux / macOS** 环境下，使用 VSCode 针对单个项目配置独立的 Python 虚拟环境（`.venv`）。

---

## 一、 创建与激活虚拟环境

### 1. 打开项目终端
在 VSCode 中打开你的项目文件夹，按下快捷键 `Ctrl + ~`（Mac 上为 `Cmd + ~`）打开内置终端。

---

### 2. 创建虚拟环境
运行以下命令，在当前项目根目录下生成 `.venv` 隔离环境：

* **Windows (PowerShell):**
  ```powershell
  python -m venv .venv

> **常见报错：** 如果提示 `Python was not found...`，请使用 `python` 而不是 `python3`。

- **Linux / macOS (Bash / Zsh):**

    ```Bash
    python3 -m venv .venv
    ```

    > **常见报错：** 如果提示 `No module named venv`，说明系统未安装 venv 包，运行以下命令补全：
    >
    > - Ubuntu/Debian: `sudo apt update && sudo apt install python3-venv`
    > - Arch Linux: `sudo pacman -S python`

### 3. 激活虚拟环境

- **Windows (PowerShell):**

    ```PowerShell
    .\.venv\Scripts\Activate.ps1
    ```

    > **如果提示“禁止运行脚本” (Execution_Policies) 报错：**
    >
    > 先在终端运行 `Set-ExecutionPolicy Unrestricted -Scope Process` 允许当前进程执行脚本，再重新激活。

- **Linux / macOS (Bash / Zsh):**

    ```Bash
    source .venv/bin/activate
    ```

当终端最左侧出现 **`(.venv)`** 前缀时，说明已成功进入虚拟环境！

## 二、 在 VSCode 中绑定虚拟环境

为了让 VSCode 的代码提示、运行和调试都使用该虚拟环境：

1. 按下快捷键 `Ctrl + Shift + P`（Mac 为 `Cmd + Shift + P`）打开命令面板。
2. 输入并选择 **`Python: Select Interpreter`**。
3. 在弹出的列表中，选择带有 **`('.venv': venv)`** 标识的那一项。
4. （可选）新建一个终端（点击终端右上角的 `+` 号），新终端会自动识别并带有 `(.venv)` 激活状态。

## 三、 在虚拟环境中安装与卸载依赖

### 1. 安装项目依赖（以 Flask 为例）

跨平台统一使用 `pip` 命令：

```Bash
pip install flask
```

*此时所有第三方包都会直接存放在当前项目的 `.venv` 文件夹内，不会污染系统全局环境。*

### 2. 撤回/卸载依赖

如果装错了包或者不想用了，直接卸载：

```Bash
# 卸载指定包
pip uninstall flask -y
```

## 四、 项目开发与清理规范

### 1. 导出与还原依赖清单（团队协作/迁移）

- **导出当前环境安装的所有包：**

    Bash

    ```
    pip freeze > requirements.txt
    ```

- **他人拿到代码后一键恢复环境：**

    Bash

    ```
    pip install -r requirements.txt
    ```

### 2. 删除/弃用项目

当这个项目不再需要时：

- 直接在文件管理器/终端中**删除整个项目文件夹**，或仅**删除 `.venv` 文件夹**：
    - **Linux / macOS 删除 `.venv` 命令：** `rm -rf .venv`
- 里面的所有插件和依赖会被**一次性彻底清理**，零残留。





# 1.2 Python 虚拟环境与依赖管理核心指南之requirements.txt

## 一、 `requirements.txt` 的作用与使用

`requirements.txt` 是 Python 项目中用来记录项目所依赖的所有第三方包及其版本的标准文本文件，核心作用是让项目能够在任何新环境中**一键复刻一模一样的运行环境**。

### 1. 核心命令
* **导出依赖清单：** 在激活虚拟环境后运行，将当前环境的所有包及版本写入文件：
  ```bash
  pip freeze > requirements.txt

- **一键还原依赖：** 拿到代码后，在新环境中运行以下命令自动安装所有依赖：

    Bash

    ```
    pip install -r requirements.txt
    ```

### 2. 开发规范

- 必须在 `.venv` 虚拟环境中执行导出，避免将全局无关的包写入。
- 永远不要将 `.venv` 文件夹提交到 Git，只需共享代码和 `requirements.txt`。

## 二、 `pip freeze` 的作用解析

`pip freeze` 的核心作用是“冻结（快照）当前 Python 环境中的所有依赖包及其确切版本”。

### 1. 核心特点

- **导出精准版本：** 按照 `包名==版本号` 的标准格式输出（例如 `flask==3.1.3`），可直接对接 `requirements.txt`。
- **包含隐式依赖：** 不仅会导出你主动安装的包（如 `flask`），还会把它的底层间接依赖（如 `click`、`werkzeug` 等）全部导出，确保环境绝对一致。
- **依赖环境上下文：** 它仅对**当前激活的环境**生效（在 `.venv` 下运行就只导出虚拟环境的包）。

### 2. `pip freeze` vs `pip list`

- **`pip list`：** 输出格式是美观的表格，是**给人看的**，方便快速查阅。
- **`pip freeze`：** 输出格式符合标准协议，是**给机器/配置文件看的**，专门用于导出和备份。



# 1.3 现代 Python 配置工具：`pyproject.toml` 指南

`pyproject.toml` 是现代 Python 项目的**统一配置文件**（根据 PEP 518 和 PEP 621 标准引入）。它的出现解决了过去 Python 项目配置碎片化（依赖写在 `requirements.txt`、打包靠 `setup.py`、测试靠 `pytest.ini` 等）的问题，实现了**项目元数据、构建工具与第三方工具配置的集中管理**。

---

## 一、 核心优势

1. **统一管理（All-in-One）：** 将构建、依赖管理及各种格式化/检查工具的配置整合至单个文件。
2. **声明构建依赖：** 明确告知 `pip` 打包或安装时需优先准备的构建后端（如 `hatchling`、`flit` 或 `setuptools`）。
3. **标准化元数据：** 遵循 PEP 621 规范，统一了项目名称、版本、作者及依赖项的声明语法。

---

## 二、 文件结构拆解

一个标准的 `pyproject.toml` 主要包含以下三大核心板块：

### 1. `[build-system]` —— 构建系统配置（必填）
指定用于打包和构建项目的工具后端。

```toml
[build-system]
requires = ["hatchling"]  # 或 ["setuptools>=61.0"]
build-backend = "hatchling.build"  # 或 "setuptools.build_meta"
```

### 2. `[project]` —— 项目元数据与依赖

替代原 `setup.py` 的作用，定义项目的基本信息与运行依赖：

```TOML
[project]
name = "my-awesome-app"
version = "0.1.0"
description = "一个基于 Flask 的示例项目"
readme = "README.md"
requires-python = ">=3.10"
authors = [
    { name = "张三", email = "zhangsan@example.com" }
]

# 项目主依赖（取代传统 requirements.txt 的核心功能）
dependencies = [
    "flask>=3.0.0",
    "requests>=2.31.0",
]

# 可选/开发环境依赖
[project.optional-dependencies]
dev = [
    "pytest>=8.0.0",
    "ruff>=0.1.0",
]
```

### 3. `[tool.<tool-name>]` —— 第三方工具配置

集中配置项目所使用的各类 Python 开发与质量控制工具：

```TOML
# 配置 pytest (单元测试)
[tool.pytest.ini_options]
minversion = "6.0"
addopts = "-ra -q"
testpaths = ["tests"]

# 配置 Ruff (代码检查与格式化)
[tool.ruff]
line-length = 88
target-version = "py311"

# 配置 mypy (静态类型检查)
[tool.mypy]
strict = true
```

## 三、 `requirements.txt` vs `pyproject.toml`

| **维度**     | **requirements.txt**           | **pyproject.toml**                       |
| ------------ | ------------------------------ | ---------------------------------------- |
| **定位**     | 简单的环境依赖锁定清单         | 现代化 Python 项目综合配置文件           |
| **内容**     | 仅包含包名与版本               | 包含项目元数据、构建引擎、依赖及工具配置 |
| **适用场景** | 个人小型测试脚本、临时环境部署 | 规范工程化项目、开源库、团队协作项目     |

## 四、 常用操作命令

### 1. 以“可编辑模式”安装当前项目

在包含 `pyproject.toml` 的项目根目录下运行，可将当前项目作为模块安装至 `.venv`，修改源码无需重新安装即可实时生效：

```Bash
pip install -e .
```

### 2. 安装开发组可选依赖（Optional Dependencies）

同步安装项目主依赖以及 `dev` 组声明的开发测试工具：

```Bash
pip install -e ".[dev]"
```



# 1.4 基于 Rust 的下一代 Python 包管理器：`uv` 指南

**`uv`** 是由 Ruff 团队（Astral）用 Rust 开发的极速 Python 包与项目管理器。

它的最大亮点就是**极致的速度**（比 `pip` 快 10 ~ 100 倍），并且它是一个 **“全能型工具”**，一站式替代了过去分散的 `pip`、`virtualenv`、`pip-tools`、`poetry`、`pipx` 甚至 `pyenv`（Python 版本管理工具）。

---

## 一、 安装 `uv`

### 1. 快捷安装命令

* **Windows (PowerShell):**
  ```powershell
  powershell -c "irm [https://astral.sh/uv/install.ps1](https://astral.sh/uv/install.ps1) | iex"

- **Linux / macOS:**

    ```Bash
    curl -LsSf [https://astral.sh/uv/install.sh](https://astral.sh/uv/install.sh) | sh
    ```

- **如果你已有 Python 环境，也可以通过 `pip` 安装：**

    ```Bash
    pip install uv
    ```

安装完成后，在终端运行 `uv --version` 验证是否成功。

## 二、 核心工作流：项目管理（极力推荐）

`uv` 引入了类似 Node.js (`npm`/`pnpm`) 或 Rust (`cargo`) 的现代工程化项目管理体验。**你甚至不需要手动创建 `.venv`，`uv` 会自动为你搞定一切。**

### 1. 初始化新项目

在空文件夹下运行：

```Bash
uv init
```

- **效果：** 会自动生成 `pyproject.toml`、`.gitignore`、`hello.py` 和 `.python-version` 文件。

### 2. 添加/卸载依赖包

```Bash
# 添加项目依赖
uv add flask

# 添加开发阶段依赖 (Dev Dependency)
uv add --dev pytest ruff

# 移除依赖
uv remove flask
```

- **效果：** `uv` 会自动将依赖写入 `pyproject.toml`，生成极速锁定文件 `uv.lock`，并自动更新 `.venv` 环境。

### 3. 一键运行代码 (`uv run`)

你不需要再手忙脚乱地去激活 `.venv`，直接使用 `uv run`：

```Bash
uv run main.py
```

- **效果：** `uv` 会自动检查 `.venv` 环境是否存在、依赖是否完整，自动补齐缺失依赖并直接执行脚本！

### 4. 团队协作拉取代码后一键同步

当同事拉取了包含 `pyproject.toml` 和 `uv.lock` 的项目后：

```Bash
uv sync
```

- **效果：** `uv` 会秒级创建一个与 `uv.lock` **完全一致**的 `.venv` 环境。

## 三、 替代传统命令（无缝替换 `pip` 和 `venv`）

如果你依然习惯传统的 `pip` 工作流，`uv` 提供了完全兼容的 `uv pip` 子命令：

| **传统命令**                      | **uv 替代命令**                                         | **特点/优势**         |
| --------------------------------- | ------------------------------------------------------- | --------------------- |
| `python -m venv .venv`            | **`uv venv`**                                           | 毫秒级创建虚拟环境    |
| `pip install flask`               | **`uv pip install flask`**                              | 比普通 `pip` 快几十倍 |
| `pip install -r requirements.txt` | **`uv pip install -r requirements.txt`**                | 秒级批量安装          |
| `pip freeze > requirements.txt`   | **`uv pip freeze > requirements.txt`**                  | 标准导出              |
| `pip-compile`                     | **`uv pip compile pyproject.toml -o requirements.txt`** | 极速解析并锁定依赖    |

## 四、 自动管理 Python 版本 (`uv python`)

以往我们需要使用 `pyenv` 或手写多个 Python 安装路径，`uv` 原生支持直接下载和切换 Python 版本：

### 1. 查看与安装 Python 版本

```Bash
# 查看本地及远程可用的 Python 版本
uv python list

# 安装指定的 Python 版本（无需手动去官网下载安装包）
uv python install 3.11 3.12
```

### 2. 为当前项目锁定 Python 版本

```Bash
uv python pin 3.11.8
```

- **效果：** 会在项目目录生成 `.python-version` 文件，之后当前项目下的所有 `uv` 命令都会强制使用该版本的 Python。

## 五、 免安装直接运行 CLI 工具 (`uvx`)

类似于 Node.js 的 `npx`，`uvx` 允许你**在不安装任何全局包、不污染当前项目**的情况下，直接运行任意 Python 命令行工具：

```Bash
# 临时运行代码检查工具 ruff
uvx ruff check .

# 临时运行代码格式化工具 black
uvx black .
```

`uvx` 会自动在临时隔离空间下载工具，运行完后即用即抛。

## 六、 总结与工具对比

| **工具**           | **速度**          | **依赖锁定 (Lockfile)** | **Python 版本管理**  | **依赖解析能力** |
| ------------------ | ----------------- | ----------------------- | -------------------- | ---------------- |
| **`pip` + `venv`** | 较慢              | 无 (需手动 freeze)      | ❌ 不支持             | 基础             |
| **`Poetry`**       | 较慢              | ✅ 支持 (`poetry.lock`)  | ❌ 不支持             | 较强但慢         |
| **`Conda`**        | 慢                | ✅ 支持                  | ✅ 支持               | 强 (体量庞大)    |
| **`uv`**           | ⚡ **极快 (Rust)** | ✅ 支持 (`uv.lock`)      | ✅ 支持 (`uv python`) | 极强且极快       |
