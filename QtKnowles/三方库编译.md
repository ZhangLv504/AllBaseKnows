# 三方库编译：QMYSQL 驱动插件

本文记录 `qsqlmysql.dll` 的完整编译与接入过程。该插件是 QtSql 访问 MySQL 的驱动实现，Qt 官方二进制包未附带，需要从 Qt 源码编译。

## 1. 需要编译的是什么

| 名称 | 来源 | 作用 |
|---|---|---|
| QtSql | Qt 安装目录（已带） | Qt 的 SQL 抽象层，`QSqlDatabase` / `QSqlQuery` |
| `qsqlmysql.dll` | **Qt 源码**中的 sqldrivers 插件 | QtSql 的 MySQL 驱动插件，运行时由 Qt5Sql 动态加载 |
| `libmysql.lib` / `libmysql.dll` | MySQL 安装目录 | MySQL 客户端库，插件调用它的 C API |
| `mysql.h` 等头文件 | MySQL 安装目录 | 编译插件时使用 |

注意两个容易混淆的点：

1. **不是 MySQL 源码**。MySQL 只提供头文件和客户端库，没有编译 MySQL 服务端。
2. **需要的是 Qt 源码**。Qt 官方 Windows 二进制出于授权原因不带 MySQL 插件，只带 SQLite/ODBC/PostgreSQL 插件；而且插件必须与 Qt 的版本、编译器、构建类型完全一致，所以用安装时附带的 Src 组件现场编译最稳妥。

`QtMySQL.dll`（独立工程中的封装库）不直接链接 `qsqlmysql.dll`；插件由 Qt5Sql 在运行时按 `sqldrivers` 目录加载。Qt 源码只是**构建期依赖**，交付时只需要 DLL 和头文件。

## 3. 依赖清单

### MySQL 侧

| 文件 | 用途 |
|---|---|
| `include/mysql.h` | 编译插件 |
| `include/mysql/*` | 编译插件 |
| `lib/libmysql.lib` | 链接导入库 |
| `lib/libmysql.dll` | 运行时客户端库 |
| `bin/jemalloc.dll` | `libmysql.dll` 的依赖 |
| `bin/libssl-1_1-x64.dll` | `libmysql.dll` 的依赖 |
| `bin/libcrypto-1_1-x64.dll` | `libmysql.dll` 的依赖 |

不要用 `lib/mysqlclient.lib`：它是 `/MT` 静态库，Qt 是 `/MD`，混用会 CRT 冲突。

### Qt 侧

| 文件 | 用途 |
|---|---|
| `lib/Qt5Core.lib`、`lib/Qt5Sql.lib` | 链接 |
| `bin/Qt5Core.dll`、`bin/Qt5Sql.dll` | 运行时 |
| `include/QtSql/5.15.2/QtSql/private/*.h` | 插件源码需要的私有头 |
| `include/QtCore/5.15.2/QtCore/private/*.h` | 私有头的间接依赖 |
| `Src/qtbase/src/plugins/sqldrivers/mysql/{main.cpp,qsql_mysql.cpp,qsql_mysql_p.h}` | 插件源码 |

Qt 二进制安装里私有头位于版本化目录（`include/QtSql/5.15.2/...`），并不在 `Qt5::Sql` 的公开 include 路径中，需要单独加入。

## 4. 为什么用 CMake 直接编译，而不走 Qt 源码树的 configure/qmake

Qt 源码树里 sqldrivers 的标准构建流程依赖 `configure` 生成的 `qtsqldrivers-config.pri`，Windows 上还需要 `mysql_config`（MySQL 官方安装不提供）。本机只安装了 Qt 二进制 + Src 组件，没有配置过完整源码树，因此直接把它当成一个普通 Qt 插件目标用 CMake 编译：

- 三个源码文件直接参与编译；
- `AUTOMOC` 处理 `main.cpp` 里的 `Q_OBJECT` / `Q_PLUGIN_METADATA`；
- 手动加入 Qt 私有头与 MySQL 头；
- 链接 `Qt5::Core`、`Qt5::Sql`、`libmysql.lib`；
- 输出为 `MODULE`，即 `qsqlmysql.dll`。

这样不需要改动 Qt 安装目录，也不需要重新配置 Qt。

## 5. CMake 实现

### 5.1 QtMySQL/CMakeLists：发现依赖

QtMySQL 只需要 Core 和 Sql；QtKnowles 另行 `find_package(Qt5 ... Core Gui Widgets Sql)`。

```cmake
find_package(Qt5 5.15.2 EXACT REQUIRED COMPONENTS Core Sql)

set(MYSQL_ROOT "E:/Software/MySQL/MySQL Server 8.0" CACHE PATH "MySQL 安装根目录")
find_path(MYSQL_INCLUDE_DIR NAMES mysql.h HINTS "${MYSQL_ROOT}/include" NO_DEFAULT_PATH)
find_library(MYSQL_LIBRARY NAMES libmysql HINTS "${MYSQL_ROOT}/lib" NO_DEFAULT_PATH)
if(NOT MYSQL_INCLUDE_DIR OR NOT MYSQL_LIBRARY)
    message(FATAL_ERROR "未找到 MySQL 开发文件，请检查 MYSQL_ROOT: ${MYSQL_ROOT}")
endif()

set(QT_SQLDRIVERS_SRC_DIR "E:/Software/Qt/5.15.2/Src/qtbase/src/plugins/sqldrivers"
    CACHE PATH "Qt sqldrivers 插件源码目录")
```

`EXACT 5.15.2` 用来保证插件源码与二进制 Qt 的版本一致，避免运行时插件加载失败。

### 5.2 插件目标

```cmake
set(_mysql_plugin_src "${QT_SQLDRIVERS_SRC_DIR}/mysql")
if(NOT EXISTS "${_mysql_plugin_src}/main.cpp")
    message(FATAL_ERROR "未找到 Qt SQL 驱动源码: ${_mysql_plugin_src}")
endif()

add_library(qsqlmysql MODULE
    "${_mysql_plugin_src}/main.cpp"
    "${_mysql_plugin_src}/qsql_mysql.cpp"
    "${_mysql_plugin_src}/qsql_mysql_p.h"
)

set_target_properties(qsqlmysql PROPERTIES AUTOMOC ON)

# 私有头所在目录：<Qt 前缀>/include/QtSql/5.15.2[/QtSql]
get_filename_component(_qt_prefix "${Qt5Sql_DIR}/../../.." ABSOLUTE)
set(_qt_version "${Qt5Sql_VERSION}")

target_include_directories(qsqlmysql PRIVATE
    "${_mysql_plugin_src}"
    "${MYSQL_INCLUDE_DIR}"
    "${_qt_prefix}/include/QtSql/${_qt_version}"
    "${_qt_prefix}/include/QtSql/${_qt_version}/QtSql"
    "${_qt_prefix}/include/QtCore/${_qt_version}"
    "${_qt_prefix}/include/QtCore/${_qt_version}/QtCore"
)

target_compile_definitions(qsqlmysql PRIVATE
    QT_PLUGIN
    QT_NO_CAST_TO_ASCII
    QT_NO_CAST_FROM_ASCII
)

target_link_libraries(qsqlmysql PRIVATE
    Qt5::Core
    Qt5::Sql
    "${MYSQL_LIBRARY}"
)

set_target_properties(qsqlmysql PROPERTIES
    PREFIX ""
    OUTPUT_NAME "qsqlmysql"
    RUNTIME_OUTPUT_DIRECTORY "${CMAKE_SOURCE_DIR}/bin/sqldrivers"
    LIBRARY_OUTPUT_DIRECTORY "${CMAKE_SOURCE_DIR}/bin/sqldrivers"
)
```

要点：

- `MODULE` 生成的是可被 Qt 动态加载的插件 DLL，不需要导出库。
- `PREFIX ""` 防止生成 `libqsqlmysql.dll`；Qt 只认 `qsqlmysql.dll`。
- 输出到 QtMySQL 的 `bin/sqldrivers`，构建后再复制到 QtKnowles 的 `bin/sqldrivers`；后者与 exe 同级，Qt 会自动在这里查找。
- `QT_NO_CAST_FROM_ASCII` / `QT_NO_CAST_TO_ASCII` 与 Qt 官方插件构建保持一致。

### 5.3 两个独立工程：QtMySQL 与 QtKnowles

目录上 `QtMySQL` 与 `QtKnowles` 并列，各自是独立 CMake 工程，不使用 `add_subdirectory`，也不链接彼此的构建目标。

`QtMySQL` 负责封装库与插件，并把交付物复制到 QtKnowles：

```cmake
# QtMySQL/CMakeLists.txt
set(QTKNOWLES_DEPLOY_DIR "${CMAKE_CURRENT_SOURCE_DIR}/../QtKnowles"
    CACHE PATH "QtKnowles 交付目录")

add_library(QtMySQL SHARED
    MySqlDatabase.cpp
    include/MySqlDatabase.h
    include/QtMySQLGlobal.h
)

target_include_directories(QtMySQL PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
)

set_target_properties(QtMySQL PROPERTIES
    RUNTIME_OUTPUT_DIRECTORY "${CMAKE_CURRENT_SOURCE_DIR}/bin"
    LIBRARY_OUTPUT_DIRECTORY "${CMAKE_CURRENT_SOURCE_DIR}/bin"
    ARCHIVE_OUTPUT_DIRECTORY "${CMAKE_CURRENT_SOURCE_DIR}/lib"
)

add_custom_command(TARGET QtMySQL POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E make_directory
        "${QTKNOWLES_DEPLOY_DIR}/bin"
        "${QTKNOWLES_DEPLOY_DIR}/lib"
        "${QTKNOWLES_DEPLOY_DIR}/publics/include"
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        "$<TARGET_FILE:QtMySQL>" "${QTKNOWLES_DEPLOY_DIR}/bin"
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        "$<TARGET_LINKER_FILE:QtMySQL>" "${QTKNOWLES_DEPLOY_DIR}/lib"
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        "${CMAKE_CURRENT_SOURCE_DIR}/include/MySqlDatabase.h"
        "${CMAKE_CURRENT_SOURCE_DIR}/include/QtMySQLGlobal.h"
        "${QTKNOWLES_DEPLOY_DIR}/publics/include"
)
```

插件同样输出到自己的 `bin/sqldrivers`，再复制一份：

```cmake
# QtMySQL/qsqlmysql/CMakeLists.txt
set_target_properties(qsqlmysql PROPERTIES
    PREFIX ""
    OUTPUT_NAME "qsqlmysql"
    RUNTIME_OUTPUT_DIRECTORY "${CMAKE_SOURCE_DIR}/bin/sqldrivers"
    LIBRARY_OUTPUT_DIRECTORY "${CMAKE_SOURCE_DIR}/bin/sqldrivers"
)

add_custom_command(TARGET qsqlmysql POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E make_directory "${QTKNOWLES_DEPLOY_DIR}/bin/sqldrivers"
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        "$<TARGET_FILE:qsqlmysql>" "${QTKNOWLES_DEPLOY_DIR}/bin/sqldrivers"
)
```

`QtKnowles` 只消费复制过来的 DLL、导入库和头文件，用一个同名 IMPORTED target 接入：

```cmake
# QtKnowles/CMakeLists.txt
add_library(QtMySQL SHARED IMPORTED)
set_target_properties(QtMySQL PROPERTIES
    IMPORTED_LOCATION "${CMAKE_CURRENT_SOURCE_DIR}/bin/QtMySQL.dll"
    IMPORTED_IMPLIB "${CMAKE_CURRENT_SOURCE_DIR}/lib/QtMySQL.lib"
    INTERFACE_INCLUDE_DIRECTORIES "${CMAKE_CURRENT_SOURCE_DIR}/publics/include"
)

target_link_libraries(QtKnowles PRIVATE
    Qt5::Core Qt5::Gui Qt5::Widgets Qt5::Sql
    QtMySQL
)
```

因此三类产物各归其位：DLL → `bin`，MSVC 导入库 `.lib` → `lib`，公开头文件 → `include`；复制到 QtKnowles 后分别落在 `bin`、`lib`、`publics/include`。

MySQL 运行时依赖（`libmysql.dll`、`jemalloc.dll`、`libssl`/`libcrypto`）不参与构建复制，部署时手动放到 exe 同目录或加入 PATH。

## 6. 配置与编译

### 6.1 qsqlmysql.dll 编译过程

`qsqlmysql.dll` 没有独立仓库，做法是把 Qt 安装目录里的 sqldrivers 源码当作普通 CMake `MODULE` 目标编译。整个过程分五步。

#### 第 1 步：确认三份输入齐全

```bat
dir "E:\Software\Qt\5.15.2\Src\qtbase\src\plugins\sqldrivers\mysql\main.cpp"
dir "E:\Software\Qt\5.15.2\Src\qtbase\src\plugins\sqldrivers\mysql\qsql_mysql.cpp"
dir "E:\Software\Qt\5.15.2\Src\qtbase\src\plugins\sqldrivers\mysql\qsql_mysql_p.h"
dir "E:\Software\MySQL\MySQL Server 8.0\include\mysql.h"
dir "E:\Software\MySQL\MySQL Server 8.0\lib\libmysql.lib"
dir "E:\Software\Qt\5.15.2\msvc2019_64\include\QtSql\5.15.2\QtSql\private\qsqldriver_p.h"
```

缺 Qt 源码时，用 Qt Maintenance Tool 勾选对应版本的 `Sources` 组件；缺 MySQL 头文件或 `libmysql.lib` 时检查 `MYSQL_ROOT`；缺私有头说明 Qt 安装不完整。

#### 第 2 步：定义插件目标

`QtMySQL/CMakeLists.txt` 负责发现 Qt、MySQL 和插件源码路径，再 `add_subdirectory(qsqlmysql)`；真正的编译设置在 `QtMySQL/qsqlmysql/CMakeLists.txt`（完整内容见 5.2），关键只有五类：

| 设置 | 值 | 作用 |
|---|---|---|
| 源码 | `main.cpp`、`qsql_mysql.cpp`、`qsql_mysql_p.h` | 插件入口 + 驱动实现 |
| 头文件 | 插件源码目录、`MYSQL_INCLUDE_DIR`、`QtSql/5.15.2[/QtSql]`、`QtCore/5.15.2[/QtCore]` | Qt 的版本化私有头目录必须在其中 |
| 宏 | `QT_PLUGIN`、`QT_NO_CAST_TO_ASCII`、`QT_NO_CAST_FROM_ASCII` | 与 Qt 官方插件构建一致 |
| 链接 | `Qt5::Core`、`Qt5::Sql`、`libmysql.lib` | `libmysql` 提供 MySQL C API |
| 输出 | `MODULE`、`PREFIX ""`、`OUTPUT_NAME "qsqlmysql"` | 生成 `qsqlmysql.dll`，无 `lib` 前缀，不产生导入库 |

`AUTOMOC ON` 是必需的：`main.cpp` 里的 `Q_OBJECT` / `Q_PLUGIN_METADATA` 需要 moc 生成插件元数据，否则 DLL 能被加载但驱动不会被识别。

#### 第 3 步：进入 MSVC 环境并配置

```bat
call "E:\Microsoft Visual Studio\2022\Enterprise\VC\Auxiliary\Build\vcvars64.bat"

cd /d "D:\AiProjs\TwoProjs\CustomProjs\otherbase\QtMySQL"

cmake -S . -B cmake-build-relwithdebinfo --fresh -G Ninja ^
      -DCMAKE_MAKE_PROGRAM=E:/Software/Qt/Tools/Ninja/ninja.exe ^
      -DCMAKE_BUILD_TYPE=RelWithDebInfo
```

配置阶段会检查 Qt 版本（`EXACT 5.15.2`）、MySQL 头文件和 `libmysql.lib`、插件源码是否存在，以及 `../QtKnowles` 交付目录是否可用；任一不满足会直接 `FATAL_ERROR`，不会拖到编译阶段才报错。

#### 第 4 步：只编译插件目标

```bat
cmake --build cmake-build-relwithdebinfo --target qsqlmysql
```

这条命令实际执行的动作：

1. AUTOMOC 处理带 `Q_OBJECT` / `Q_PLUGIN_METADATA` 的 `main.cpp`，生成 `qsqlmysql_autogen/mocs_compilation.cpp`；
2. `cl.exe` 编译 `main.cpp`、`qsql_mysql.cpp`、`mocs_compilation.cpp`；
3. 链接 `Qt5Core.lib`、`Qt5Sql.lib`、`libmysql.lib`；
4. 生成 `QtMySQL/bin/sqldrivers/qsqlmysql.dll`。

成功时最后一行类似：

```
[9/9] Linking CXX shared module D:\...\QtMySQL\bin\sqldrivers\qsqlmysql.dll
```

`MODULE` 只产出 DLL，不会生成 `qsqlmysql.lib`，找不到导入库是正常现象。

#### 第 5 步：复制并验证

插件的 POST_BUILD 会把 DLL 复制到 `QtKnowles/bin/sqldrivers`。验证分两层：

```bat
:: 查看运行时依赖，需要 MSVC 环境
dumpbin -dependents "D:\AiProjs\TwoProjs\CustomProjs\otherbase\QtMySQL\bin\sqldrivers\qsqlmysql.dll"
```

本机实际输出包含：

```
Qt5Sql.dll
libmysql.dll
Qt5Core.dll
VCRUNTIME140_1.dll
VCRUNTIME140.dll
```

随后运行宿主程序打印驱动列表：

```cpp
qInfo() << QSqlDatabase::drivers();
```

出现 `QMYSQL` 说明插件被 Qt5Sql 成功加载、版本匹配、依赖可解析。没有出现时按第 10 节排查。

### 6.2 两个工程的完整构建

必须先进入 MSVC 环境，否则 Ninja 找不到 `cl.exe`。两个工程按顺序构建：先 QtMySQL（产生并复制交付物），再 QtKnowles（消费副本）。

```bat
call "E:\Microsoft Visual Studio\2022\Enterprise\VC\Auxiliary\Build\vcvars64.bat"

:: 1. 构建 QtMySQL：生成 DLL、导入库、头文件与插件，并复制到 ../QtKnowles
cd /d "D:\AiProjs\TwoProjs\CustomProjs\otherbase\QtMySQL"

cmake -S . -B cmake-build-relwithdebinfo --fresh -G Ninja ^
      -DCMAKE_MAKE_PROGRAM=E:/Software/Qt/Tools/Ninja/ninja.exe ^
      -DCMAKE_BUILD_TYPE=RelWithDebInfo

cmake --build cmake-build-relwithdebinfo

:: 2. 构建 QtKnowles：只读取 bin/lib/publics/include 下的副本
cd /d "D:\AiProjs\TwoProjs\CustomProjs\otherbase\QtKnowles"

cmake -S . -B cmake-build-relwithdebinfo --fresh -G Ninja ^
      -DCMAKE_MAKE_PROGRAM=E:/Software/Qt/Tools/Ninja/ninja.exe ^
      -DCMAKE_BUILD_TYPE=RelWithDebInfo

cmake --build cmake-build-relwithdebinfo
```

补充说明：

- 两个工程各自独立配置。QtKnowles 不知道 QtMySQL 的源码，只读取复制后的 `bin`、`lib`、`publics/include`。
- QtKnowles 不会自动触发 QtMySQL 的重建；改了封装库代码后，先重新构建 `../QtMySQL`。
- 只编译插件：见 6.1 第 4 步。
- `--fresh` 用于丢弃旧缓存；目录拆分后旧的 `CMAKE_HOME_DIRECTORY` 不再适用。
- 使用 Ninja 单配置生成器；如果换 Visual Studio 多配置生成器，输出目录会带 `RelWithDebInfo/` 子目录，需要相应调整 `RUNTIME_OUTPUT_DIRECTORY`。

## 8. 部署

exe 位于 `bin`，运行时以 `bin` 为工作目录：

1. `Qt5Core.dll`、`Qt5Sql.dll` 等 Qt 库放进 `bin`（`windeployqt` 可处理）。
2. `bin/sqldrivers/qsqlmysql.dll` 存在。
3. `libmysql.dll`、`jemalloc.dll`、`libssl-1_1-x64.dll`、`libcrypto-1_1-x64.dll` 与 exe 同在 `bin`（或在 PATH 中）。

`windeployqt` 不会复制 `qsqlmysql.dll` 和 `libmysql.dll`，需要手动带上。给其他工程使用时，带上 `bin`、`lib/QtMySQL.lib` 和 `publics/include`。

## 9. 验证

### 9.1 插件是否被加载

```cpp
qInfo() << QSqlDatabase::drivers();
```

输出中应包含 `QMYSQL`（以及别名 `QMYSQL3`）。如果没有，优先检查：

- `bin/sqldrivers/qsqlmysql.dll` 是否在 exe 同级目录；
- `libmysql.dll` 及其依赖是否可找到；
- 插件与 Qt 的构建类型是否一致（release / debug）。

### 9.2 连接测试

```cpp
qtmysql::MySqlDatabase db;
QString error;
if (!db.connect("127.0.0.1", 3306, "zl_study_db", "your_password", &error))
    qCritical().noquote() << error;
```

服务未启动时的典型错误：

```
QMYSQL: Unable to connect: Can't connect to MySQL server on '127.0.0.1:3306' (10061)
```

能返回该错误说明插件、libmysql、网络路径都已正常工作，只是 MySQL 服务未监听。

## 10. 踩坑记录

| 现象 | 原因 | 处理 |
|---|---|---|
| `fatal error C1083: 无法打开 QtSql/private/qsqldriver_p.h` | 私有头不在 `Qt5::Sql` 公开 include 路径 | 手动加入 `include/QtSql/5.15.2` 与 `.../QtSql`（QtCore 同理） |
| Qt 官方源码构建找不到 `qtsqldrivers-config.pri` | 需要先对 Qt 源码树执行 configure | 不重建 Qt，直接用 CMake 编译插件 |
| `mysql_config not found` | Windows 版 MySQL 不提供该脚本 | 直接指定 MySQL 头文件和 `libmysql.lib` |
| 插件加载失败、驱动列表没有 QMYSQL | Debug/Release 不匹配 | 插件必须与 release 版 Qt 一致；保持 `RelWithDebInfo`/`Release` |
| 链接或运行崩溃 | 误用 `mysqlclient.lib`（`/MT` 静态库） | 只用 `libmysql.lib` + `libmysql.dll` |
| 运行时提示找不到 `libmysql.dll` | DLL 在 MySQL 的 `lib/` 而不是 `bin/` | 从 `lib/` 拷贝，并补齐 `bin/` 下的 OpenSSL、jemalloc |
| 中文/emoji 乱码 | 服务端默认字符集是 utf8mb3 | 封装库连接后执行 `SET NAMES utf8mb4`，建表用 `utf8mb4` |
| MySQL 8 认证失败 | 默认 `caching_sha2_password` | MySQL 8 客户端默认优先 TLS，本机验证可正常连接；若失败可显式提供 SSL 参数或改用 `mysql_native_password` 账号 |
| 旧构建目录配置报错 | 缓存中的源码目录指向迁移前路径 | `cmake --fresh` 重新配置 |

## 11. 如果已有匹配的预编译插件

如果拿到与当前 Qt 完全匹配的 `qsqlmysql.dll`，就不需要编译：

1. 把 `qsqlmysql.dll` 放到 `<exe 目录>/sqldrivers/`；
2. 保证 `libmysql.dll` 及依赖可用；
3. 删除或跳过 `qsqlmysql` 目标。

判断是否匹配的条件：Qt 版本（5.15.2）、编译器（MSVC 2019/2022 x64）、构建类型（release）三者一致。

## 12. 版本升级注意

Qt 升级（例如换到 6.x）后：

- 驱动插件源码路径改为对应版本的 `qtbase/src/plugins/sqldrivers/mysql`；
- Qt6 的 sqldrivers 已改为 CMake 工程，可直接 `add_subdirectory` 或按其 `CMakeLists.txt` 构建；
- 插件输出名、私有头路径和 CMake 包名（`Qt6::Sql`）都要同步调整。
